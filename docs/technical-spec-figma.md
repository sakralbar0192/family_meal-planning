# Техническое задание: интерактивный макет веб-приложения планирования питания

**Оглавление папки `docs/`:** [README.md](./README.md).

## Принятые решения

- **Язык интерфейса в макетах и ТЗ:** русский.
- **Файл Figma:** по задумке — отдельный новый файл; фактически первичная сборка выполнена в подключённом через MCP файле (см. раздел «Ограничения среды»). Для продакшн-гайда рекомендуется **скопировать страницы** в новый файл команды или обновить тариф Figma.
- **Иконки:** рекомендуется набор **[Lucide](https://lucide.dev/)** (открытая лицензия, единый стиль с минималистичным UI).
- **Карточка заметки (`DS / NoteCard`):** используется в **экране просмотра рецепта** (краткая заметка / подсказка) и может дублироваться в **планировщике** для заметок к дню; отдельно от карточки рецепта.
- **Доменные границы и материал для Event Storming:** [domain-contexts-event-storming.md](./domain-contexts-event-storming.md) (стратегическая карта контекстов, единый язык, тактические заготовки). Бизнес-правда по функциям — в [business-doc.md](./business-doc.md).

## Ограничения среды (зафиксировать для команды)

1. **Тариф Figma Starter:** доступно **не более 3 страниц** в файле. **Актуальные страницы** (аудит MCP vibma, 2026-04-04):
   - **`Design`** (`3325:42`) — основной холст: секции **Desktop** (`3339:128`), **Tablet** (`3356:457`), **Mobile** (`3356:919`); часть экранов и touch-оверлеев — **прямые дети страницы** (напр. `SCR / Список покупок`, `MOD / Календарь — из рецепта — Tablet 768` на корне).
   - **`DDD`** (`3339:81`) — доска Event Storming и карт контекстов (секция `3372:1312`; см. [domain-contexts-event-storming.md](./domain-contexts-event-storming.md)). Отдельной страницы **`00 — IA`** в файле **нет** — материал ИА перенесён/сосредоточен здесь и в сценарных фреймах на **Design**.
   - **`01 — Токены и UI Kit`** (`3339:82`) — секции **A. Токены**, **B. UI Kit**, **C. DS** (UiAppHeader и UiButton — варианты Storybook).
2. **Прототип и иерархия:** для целей **`NAVIGATE`** целевой фрейм часто должен быть **прямым потомком страницы** `Design` (не вложен в **SECTION**), иначе vibma/Figma могут отклонить связь. **`OVERLAY`** на **desktop** проверен: кнопка **«Планировщик»** (`3339:133`) → **`OVERLAY`** на **`MOD / Календарь`** (`3356:1634`), при том что модалка лежит внутри **SECTION `Desktop`** — связь **работает** (2026-04-04). Часть **tablet/mobile** оверлеев импорта и календаря «из рецепта» по-прежнему вынесена **прямыми детьми `Design`** для стабильности прототипа.
3. **Переменные:** в текущем файле коллекция поддерживает **один режим** (нельзя добавить второй `Dark` в ту же коллекцию). Светлая тема задана переменными коллекции **`Notes / Tokens`**. Значения **тёмной темы** приведены в таблице ниже — для реализации в коде и для ручного перекрашивания тёмных макетов. В документе через MCP зафиксированы **две** записи с именем `Notes / Tokens` (одна без переменных) и пустая **`Питание — токены`** — при уборке файла оставить одну рабочую коллекцию; в рабочей коллекции **39** переменных (см. список ниже).
4. **Шрифты:** используется **Inter** (после настройки локальных шрифтов в Figma Desktop). В макетах и мастер-компонентах добавлен **русский текст** (кнопки, поля, карточки, планировщик, список покупок, модальная оболочка). При смене машины без Inter повторите установку шрифта или замените семейство через меню Figma.

## Коллекция переменных «Notes / Tokens»

**Цвета (светлая тема в Figma):** `color/bg`, `color/bg-elevated`, `color/surface`, `color/border`, `color/text-primary`, `color/text-secondary`, `color/text-muted`, `color/accent`, `color/accent-hover`, `color/accent-pressed`, `color/success`, `color/error`, `color/warning`, **`color/overlay`** (scrim под модалками, ~45% opacity), **`color/text-on-accent`** (текст на primary / акцентном фоне), **`color/focus-ring`** (обводка фокуса, a11y).

**Прочее (FLOAT):** **`opacity/overlay`** (0.45 — для спеки рядом с `color/overlay`), **`font-size/caption`**, **`font-size/body`**, **`font-size/title`**, **`font-size/heading`**, **`breakpoint/desktop-min`** (1200), **`breakpoint/tablet-min`** (768), **`breakpoint/mobile-width`** (390).

На странице **`01 — Токены и UI Kit`** в фрейме «Справочник токенов» добавлен текстовый блок со списком дополнительных имён для команды.

**Компонент `UiAppHeader`:** единый референс разметки, слотов и утилитарных ссылок верхней панели — фрейм **`UiAppHeader — все сторис`** (node **`3390:2430`**, секция **C** на той же странице); отступы и фон — токены **`space/md`**, **`space/xl`**, **`color/bg-elevated`**, **`color/border`**. Экранные фреймы **`SCR/*`** остаются контекстом целых страниц; варианты TopBar для имплементации — по этому фрейму и Storybook в коде.

**Компонент `UiButton`:** сводная матрица вариантов (primary / secondary / danger × md / sm, default и disabled) и подписи к text-видам шапки и легаси `.btn` — фрейм **`UiButton — все сторис`** (node **`3394:1513`**, та же секция **C**); вертикальный авто-лейаут и внутренние отступы совпадают с фреймом **`3390:2430`** (padding **48**, item spacing **48**).

### Исключения и техдолг по привязке к токенам (lint)

Проверка **`lint(method:"check", rules:["token"])`** (vibma):

- Страница **`01 — Токены и UI Kit`** (`3339:82`): много срабатываний **`hardcoded-token`** (padding, itemSpacing, strokeWeight на мастерах `DS / *` и паттернах) — числа совпадают с токенами (`space/*`, `radius/*`), но **не привязаны** к переменным FLOAT; **`hardcoded-color`** / **`no-text-style`** на единичных текстовых слоях в кнопках (подписи «Действие», «Удалить», заголовок паттерна периода).
- Секция **`Desktop`** (`3339:128`): **`hardcoded-token`** на экранных фреймах (TopBar, Toolbar, Grid, инстансы карточек) — типичный техдолг прототипа.

**Рекомендация:** постепенно привязывать отступы мастер-компонентов к `space/*` и `radius/*`; для текста — стили текста или переменные, где применимо. До миграции документ считается согласованным, если **семантика** совпадает с таблицей токенов выше.

## Этап 1. Анализ требований и ИА

### Разделы приложения

1. Вход / регистрация (упрощённо).
2. Главная / дашборд (опционально объединить с планировщиком и недавними рецептами).
3. Библиотека рецептов.
4. Просмотр рецепта.
5. Создание / редактирование рецепта.
6. Импорт по URL.
7. Планировщик питания (неделя, слоты приёмов пищи).
8. Список покупок.
9. Профиль / настройки (минимум).

### Ключевые переходы

- Вход → дашборд / библиотека.
- Библиотека → карточка рецепта (клик по телу) → просмотр; импорт; на **desktop** и **tablet** кнопка **«Планировщик»** → **оверлей с календарём** (`MOD / Календарь` / **`MOD / Календарь — Tablet 768`**) → **клик по числу дня** → планировщик; на **mobile** тот же макет календаря оформлен как полноэкранный **`SCR / Календарь — Mobile 390`** (**`NAVIGATE`** из библиотеки — смена экрана, без стека оверлея); чип **«В план»** на карточке → модалка **«Добавить в план»** (фреймы **`3387:2326`**, **`3387:2342`**, тост **`3387:2359`** — см. **«Статус синхронизации»** и этап 5; демо-связь на первой desktop-карточке).
- **Планировщик** → панель **«Список покупок на период»** → **«Сформировать список покупок»** → список покупок (основной сценарий MVP).
- **Список покупок** → **«Изменить период»** / «К планировщику» → планировщик (единый источник правды для дат).
- Рецепт (просмотр) → **«В план»** → **оверлей месячного календаря** (`MOD / Календарь — из рецепта`) → **клик по дню** → **`SCR / Планировщик — из рецепта`**: в поле поиска панели рецептов **уже введено название этого блюда** (в продукте — автоподстановка; в макете — демо-текст), далее перенос карточки в слот.

### Состояния на экранах

Для каждого экрана в финале макета: **пусто**, **загрузка**, **ошибка**, **успех** (хотя бы один вариант на экран в backlog после MVP-прототипа).

**Артефакт в Figma:** отдельной страницы **`00 — IA`** в файле **нет** (аудит 2026-04-04). Контекст и потоки: страница **`DDD`** (`3339:81`) — Event Storming; сценарные экраны и аннотации — на **`Design`**. Ранее ссылался узел `3355:590` в «IA — поток экранов…» — при поиске в актуальном файле **перепроверить** или опираться на этот документ и [design-plan.md](./design-plan.md) п. 3.

### DS / Input / Field — выравнивание с кнопками

**Проблема:** у мастера два блока по вертикали — **подпись** (`Label …`) и **поле** (`Field`). Высота инстанса больше, чем у **`DS / Button / *`** (**`button/min-height`** = **36**). В горизонтальном `auto layout` с **`counterAxisAlignItems: CENTER`** центрируется весь инстанс, а не строка ввода — ряд с кнопками выглядит «сломанным».

**Реализация в файле (мастер `DS / Input / Field`, `3339:105`):**

- Добавлено свойство компонента **`Show label`** (тип **BOOLEAN**, по умолчанию **true**).
- Фрейм **`Label (текст в макете)`** (`3339:106`) привязан к этому свойству: **`visible`** ↔ **`Show label`** (через `componentPropertyReferences` на слое подписи).
- При **`Show label = false`** подпись не участвует в вёрстке, высота инстанса совпадает с **полем** (**`minHeight` 44**), выравнивание с кнопками в одной строке корректное.
- Инстансы в **тулбарах** (все найденные в прототипе с родителем `Toolbar`) переключены на **`Show label = false`**; смысл бывшей подписи переносится в **плейсхолдер** поля там, где нужно.
- Инстансы в **боковой панели планировщика**, **формах** и **модалках** оставьте с **`Show label = true`**, если нужна внешняя подпись.

*После копирования файла* имя ключа свойства в API может стать вроде `Show label#<id>` — в UI Figma отображается как **Show label**.

- **Прототип:** связи **только внутри одной ширины** (768→768, 390→390), чтобы Present не перескакивал на desktop.

- ИА и прототип согласованы с [design-plan.md](./design-plan.md): **6** фиксированных приёмов пищи в колонках дня; список покупок с **периодом** и **«Изменить период»**; вход на список через календарь периода (**`MOD / …`** на desktop, **`SCR / Календарь — период покупок — Mobile 390`** на mobile — см. этап 4); **«В план» с экрана рецепта** → **календарь** → планировщик с **предзаполненным поиском** по названию блюда. **«В план» с карточки библиотеки** → модалка (**`3387:2326`**, **`3387:2342`**) и тост (**`3387:2359`**) — см. этап 5 и **«Статус синхронизации»** (демо на первой карточке desktop).
- Сценарии: импорт (**модалка URL** `3363:879` → **загрузка** `3363:890` → **успех** `3352:183` / **`3363:2048`** или **ошибка** `3363:901`), редактор, вход, удаление (оверлей), **из библиотеки в планировщик через месячный календарь и выбор дня**, **с экрана рецепта — «В план» → `MOD / Календарь — из рецепта` → `SCR / Планировщик — из рецепта` с предзаполненным поиском**, **с карточки библиотеки — чип «В план» → модалка (два шага) → тост** (см. `3387:*`), формирование списка покупок **через «Список покупок» / «Изменить период» → календарь периода → «Показать список»**. Экран **профиля** — **в backlog**, пока не появится макет.
- Есть пустое состояние библиотеки, загрузка импорта, модалка ошибки; остальные состояния экранов можно наращивать отдельными фреймами.
- Три ширины — дубли tablet/mobile (см. матрицу этапа 4); планировщик на 768/390: **дополнить панелью периода** и проверить **шесть слотов** вручную при необходимости.
- Дизайн-система: компоненты `DS / *`, переменные `Notes / Tokens`; в секции B — **паттерны** периода, скелетон импорта; строка ингредиента в редакторе — **`DS / Editor / IngredientRow`** (см. таблицу этапа 3).
- Разработчик понимает логику переходов по прототипу и этому документу без устных пояснений.

## Примечание по MCP (vibma)

1. `connection.create` / `connection.get` — связь с плагином в Figma.
2. `document` — страницы (лимит Starter).
3. `variable_collections` / `variables` — токены.
4. `components` / `instances` — UI Kit и экраны.
5. `frames` — секции, фреймы, **create** (вызов `method:"create", type:"auto_layout", items:[...]`), **clone/update/delete/reparent/export**.
6. `prototyping` — реакции на **экземплярах, фреймах, тексте**. **`NAVIGATE`:** целевой кадр часто должен быть **прямым потомком страницы `Design`** (не вложен в `SECTION`), иначе vibma может отклонить связь. **`OVERLAY`:** проверено на desktop — цель может лежать в **SECTION `Desktop`** (пример: **`3339:133` → `3356:1634`**). Часть touch-оверлеев (импорт, календарь «из рецепта» tablet) — **прямые дети `Design`**. Актуальную иерархию смотреть **`document.get`** / **`frames.list`** на странице **`Design`**.
7. `lint` — проверка токенов и композиции.
